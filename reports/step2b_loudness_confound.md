> 坏掉的是"识别信号在哪些特征上"的方法，不是信号本身。

## 2. 判定：响度是**干扰**，不是信号

`diag_loudness.py` 按预设规则输出「解释 A（真信号）」。

**但需如实说明：实际结果落在预设的三个分支之外。** 预设规则考虑的是
"AUC 下降多少"，而实测 AUC **上升**了——这是我事先没有覆盖的第四种情况。
准确的描述是：

> 绝对响度是**数据集特异的指纹**，去掉后跨源泛化反而变好。

机制很具体：DEAM 是混合曲库，PMEmo 是流行歌副歌（普遍经过响度战争式的重压缩母带），
两者的响度分布本就不同。模型原来学到"DEAM 里响的 = 高唤醒"，搬到 PMEmo 就失准。
归一化洗掉了这一层。

**关键结论：构念混淆（解释 B）被排除。** 模型不是只在学响度，
`step2_real_labels.md` §4 标记的阻塞项**解除**，规则库工作可以继续。

`mfcc1_mean` 仍留在 top-20（10.7），但**语义已变**——电平归一后它不再表征绝对响度，
而是频谱倾斜。不能再按"响度规则"解读它。

## 3. 新的共识特征集

首次过门槛的 6 个，**没有一个是绝对电平**：

| 特征 | 声学含义 | 对应笔记 §4 的预期 |
|---|---|---|
| `spec_contrast6_dmean` | 高频段谱对比度的变化速率 | 未预期（时序类）|
| `onset_rate` | 突发事件密度 | ✅ "无突发 onset" |
| `spec_contrast1_p10` | 低频段谱对比度下分位 | 未预期 |
| `spec_contrast2_p10` | 次低频段同上 | 未预期 |
| `spec_rolloff_mean` | 频谱滚降点 | 部分对应"高频刺耳带" |
| `zcr_p50` | 过零率中位数（≈高频含量） | 部分对应"高频刺耳带" |

结构上全是「频谱形状 + 时序变化率」。笔记 §4 预期的**频谱形状方向部分回来了**，
但载体不是 1/f 斜率（排名仍靠后），而是**谱对比度和滚降点**。

## 4. 方法学决定：响度归一化设为默认

四项同时改善（跨源 AUC / recall / 适用域覆盖 / SHAP 稳定性），
唯一代价是组内 CV 掉 0.01——而组内 CV 本来就只是 sanity check，不是成绩单。

**后续 Layer B / Layer C 一律在响度归一化基础上做。**

⚠️ 这条对产品也有含义：设备端做音频筛选/打分时，**必须先做响度归一化再送模型**，
否则会重现同样的数据集指纹问题。这一点要写进 L2 引擎的接口约定。

## 5. 仍未解决的

- **stacking 依然不成立**：归一化后 Stacking 0.9244 < RF 0.9304。
  与 `step2_real_labels.md` §2 的结论一致——需要 Layer B/C 提供表示多样性。
- **SHAP 交集 6 个是卡线通过**，且只有 Layer A 一层。
  可以出规则草案 v0.1，但 `声学规则库_v1.md` 应等 Layer B 补齐后再定稿。
- **1/f 斜率仍然排名靠后**，与笔记 §4 的核心假设不符。
  Layer B 的 sharpness / roughness / fluctuation strength 进来后再复核——
  有可能 1/f 斜率想捕捉的东西被心理声学量更直接地表达了。
