# 合成网格 + 闭环生成：闸拦住了我们，而不是让我们自欺

- run_id：`20260727T171314Z_synthesis_grid_closed_loop`
- 网格：slope(5) × onset_rate(5) × flux(4) × seed(3) = **300 个候选**
- oracle：音乐域（DEAM）+ 环境声域（Emo-Soundscapes）两个 XGBoost
- 闸：适用域 / Rashomon 一致（8 模型）/ 域之墙 / 零分布

---

## 0. 先说结论

**300 个候选，0 个通过四道闸。卡死的是适用域：100% 的合成音频落在训练分布之外。**

这不是闸太严，而是一个实质结论：

> **这些模型无法有效给合成音频打分。**
> 它们只见过自然录音，参数化噪声对它们而言全部是外推。

因此本次的剂量–反应曲面**只能读作模型的外推行为，不能读作对人的预测**。

---

## 1. 操纵检查：第一版实现完全失控，被检查抓住 ⭐

**这一节本身是个方法学发现。**

初版 `synthesis.py` 用「时变低通」实现 flux 轴。操纵检查结果：

| slope 参数 | 实测 slope_1f（初版） |
|---|---|
| 1.0 | −3.08 |
| 2.0 | −1.34 |

**非单调，完全失控。** 原因：低通滤波器的滚降主导了测得的谱斜率；
滤波器逐块切换本身又制造瞬态，污染 onset 轴（参数 0 → 实测 3.30）。

改为**时变谱倾斜**（在 STFT 幅度上施加 `f^(−slope_t/2)`）后：

| slope 参数 | 0.0 | 0.5 | 1.0 | 1.5 | 2.0 |
|---|---|---|---|---|---|
| 实测 slope_1f | +0.33 | −0.15 | −0.64 | −1.13 | −1.57 |

完美单调。

### 修正后的操纵检查与串扰

| 操纵（参数 → 目标描述符） | ρ |
|---|---|
| slope → `slope_1f` | **−0.906** |
| onset → `onset_rate` | **+0.660** |
| flux → `spec_centroid_dmean` | **+0.655** |
| flux → `spec_flatness_std` | +0.560 |

| 串扰（应远小于上表） | ρ |
|---|---|
| onset → `slope_1f` | **−0.025** ✅ 正交 |
| slope → `onset_rate` | +0.197 |
| flux → `slope_1f` | +0.291 |
| **onset → `spec_centroid_dmean`** | **+0.477** ⚠️ |

⚠️ **onset 轴与 flux 轴不正交**：注入瞬态本身是宽带事件，
必然搅动频谱重心变异（0.477，接近 flux 自身的 0.655）。

**因此「合成让三轴按构造完全受控」这一说法必须收回。**
准确表述：**合成的特异性显著优于修改真实音频（slope 轴串扰仅 −0.025），
但 onset 与 flux 两轴仍存在实质串扰。**

### 附带教训

flux 轴最初测得 ρ 仅 0.227，一度以为是合成器不行；
换用 `spec_centroid_dmean` 后升到 0.655 —— **是测量对象选错，不是操纵失败**。
时变谱倾斜直接移动的是频谱重心，不是谱对比度。

## 2. 四道闸：0/300 通过

| 闸 | 通过率 | 说明 |
|---|---|---|
| **适用域** | **0.0%** | 全部落在训练分布外 |
| Rashomon 一致 | 31.7% | 仅三成候选被多数近优模型认可 |
| 域之墙 | 73.0% | 多数候选两域模型都判低唤醒 |
| 零分布 | 4.3% | 仅少数超出真实语料参考分布 |

**适用域是绑定约束。** 合成音频与自然录音在特征空间中根本不重叠。

---

## 3. 对抗样本：整个「最助眠」四分位都是假的 ⭐⭐

oracle 判为最助眠的四分位（75 个）中，**76 个被闸拒（≈100%）**。

它们的共同特征：**`slope = 0.0`，即白噪声**。
模型在训练分布外把白噪声外推成了极低唤醒。

**若不设闸，这 76 个会被当作「发现」直接进候选库。**

这是 Goodhart 定律最直接的演示：拿感知模型当适应度函数去优化，
找到的是模型盲区，不是真正让人放松的声音。

## 4. 剂量–反应（仅可读作模型外推行为）

| 轴 | ρ | 边际均值（oracle 预测唤醒，越低越助眠） |
|---|---|---|
| `onset_rate` | **+0.514** | 0→−0.148  1→−0.115  2→−0.076  4→−0.053  6→−0.025 |
| `flux_hz` | +0.363 | 0→−0.152  0.25→−0.060  0.75→−0.059  1.5→−0.063 |
| `slope` | +0.161 | 0→−0.091  0.5→−0.105  **1.0→−0.114**  1.5→−0.100  2.0→−0.006 |

- **onset**：干净单调，突发越多越唤醒 —— 与规则库一致
- **flux**：阈值型而非渐进型 —— 只要有变化就抬高唤醒，再快也不多抬
- **slope**：倒 U，最低点在 **1.0（粉噪）**，两端上升

粉噪最优与民间常识吻合，但**这是在适用域外得到的**，
可能是巧合，也可能说明模型外推方向合理 —— 本数据无法区分。

## 5. 对「合成修掉特异性局限」这一说法的最终裁定

此前（`RESULTS_SUMMARY` D-3、`step6` §6）把干预特异性记为
「物理约束，无法消除」，随后又称合成可以修掉它。**两者都需要修正**：

| 说法 | 裁定 |
|---|---|
| 「修改真实音频时特异性不足是物理约束」 | ✅ 成立 |
| 「合成能按构造完全控制三轴」 | ❌ 收回 —— onset/flux 串扰 0.477 |
| 「合成的特异性优于修改」 | ✅ 成立 —— slope 轴串扰仅 0.025 |
| 「合成网格给出干净的剂量–反应」 | ⚠️ 曲面本身干净，但**在模型适用域外**，不可作为对人的预测 |

---

## 6. 闭环生成：当前设计堵死，但堵得有价值

**按当前设计走不通**：生成器产出参数化噪声 → 100% 域外 → oracle 打分无效。

两条可能的出路：

1. **换生成器**：用 AudioLDM / Stable Audio 生成**自然主义**音频，
   使候选落在训练分布内。代价是失去参数级的精确控制。
2. **扩训练域**：把合成音频纳入训练语料。
   但那需要合成音频的**真人标注** —— 回到人体实验，不是 in-silico 能解决的。

**无论走哪条，四道闸都必须保留。** 本次的价值恰恰在于：
它在我们把 76 个白噪声当成「发现」之前拦住了。

若按朴素做法（优化到模型给分最高就收工），本项目会产出一份
「AI 发现的最佳助眠声音清单」，全是白噪声，且完全无法验证。
